# 변경 판단 정확도 평가

> 측정일 2026-10-25 · 모델 gpt-4o-mini (temperature 0) · 병원 분야 테스트 문장 86개 × 3회 반복
> 앱과 같은 분석 경로로 측정 (여러 문장 안내는 문장마다 따로 분석, #38) · 측정 중 AI 호출 실패 0회
> 다시 측정: `backend` 폴더에서 `python -m scripts.report --provider openai --repeat 3` (표가 화면에 출력되며, 이 문서의 숫자는 손으로 갱신)

## 한 줄 요약
**같은 AI 답변이라도 규칙 검증을 거치면 틀린 정보 저장이 12건 → 0건으로 줄었습니다.**
문장 정답률은 76% → 95%로 올랐고, 대신 사용자에게 확인을 묻는 횟수가 2건 → 9건으로 늘었습니다.

## 규칙 검증 효과 (86문장 × 3회)

| 판단 방식 | 문장 정답 | 잘못된 저장 | 확인 요청 | 놓친 반영 |
|---|---|---|---|---|
| ① AI 단독 | 65.3 / 86 (76%) | 12건 | 2건 | 1건 |
| ② 기본 규칙 | 66 / 86 (77%) | 11.3건 | 3.7건 | 2건 |
| ③ 안전장치 추가 (현재) | **82 / 86 (95%)** | **0건** | 9건 | 2건 |

- **① AI 단독**: AI가 말한 변경 유형대로 저장 (언급이면 무시, 불확실이면 확인만)
- **② 기본 규칙**: 프로젝트 시작 때의 verifier 8개 규칙 (근거 확인, 신뢰도, 같은 값 등)
- **③ 안전장치 추가**: 실제 AI 오류를 보고 추가한 규칙 (값 정규화, 불확실 표현, 값 형식, 안내 대상, 상태 설명, 같은 값 등)
- 세 방식에 **같은 AI 답변**을 넣었으므로 차이는 판단 방식에서만 나옵니다. 소수는 3회 평균입니다.
- ③의 "잘못된 저장 0건"은 3회 모두 0건입니다.

용어
- **잘못된 저장**: 저장 결과 '현재 정보'가 틀리게 된 문장 수. 같은 값을 다시 저장하거나 '1시'·'오후 1시'처럼 표기만 다른 경우는 세지 않습니다.
- **확인 요청**: 자동 반영하지 않고 사용자에게 물은 횟수. 안전을 위해 치르는 대가입니다.
- **놓친 반영**: 반영해야 하는데 마지막 판단이 반영이 아닌 항목 수. ③의 2건 중 1건("대기 번호를 잘못 안내드렸습니다. 15번입니다.")은
  두 문장이 각각 판단되면서 마지막 판단이 "같은 값"으로 끝난 경우로, **저장된 값(15번)은 정답**입니다.

## 읽는 법 (발표 포인트)
1. **AI는 대부분 맞히지만, 틀릴 때가 위험합니다.** AI 단독은 76%를 맞히지만 12문장에서 틀린 정보를 저장합니다.
   이 서비스에서는 "모르면 묻기"보다 "틀리게 저장하기"가 훨씬 나쁩니다.
2. **처음 만든 기본 규칙만으로는 효과가 거의 없었습니다 (①과 ②가 거의 같음).** AI는 근거를 지어내거나 신뢰도를 낮게 주는 일이 거의 없었고,
   실제 오류는 "다른 환자를 부르는 안내", "진료실 상태 설명" 같은 **안내 문장 특유의 함정**에서 나왔습니다.
   평가 → 오류 분석 → 규칙 추가를 반복해 ③을 만들었습니다.
3. **대가는 확인 요청 7건 증가입니다.** 86문장 중 9번 사용자에게 묻습니다. 대부분 "내 번호를 등록하면 자동으로 구분해요"처럼
   사용자가 정보를 등록하면 줄어드는 확인입니다.

## 처음 보는 문장으로 재기 (준비됨, 문장 모으는 중)
③의 규칙은 아래 86문장을 보며 만들었기 때문에, **규칙을 만들 때 안 본 문장**으로 따로 재야 실제 실력을 알 수 있습니다.
1. 팀원(A·B)이 실제로 들을 법한 안내를 써서 `backend/tests/fixtures/heldout.json`에 넣습니다. 형식은 `sentences.json`과 같습니다.
   ```json
   {"name": "진료실 뒤 채혈 시간", "facts": {"room": "3번"}, "text": "채혈은 2시 반에 합니다.", "expect": {"exam_time": ["applied", "오후 2시 30분"]}}
   ```
2. **규칙·프롬프트를 고치기 전에** 먼저 잽니다: `python -m scripts.report --provider openai --repeat 3 --fixtures tests/fixtures/heldout.json`
3. 결과를 이 문서에 그대로 적고, 그다음에 틀린 문장을 고칩니다. (고친 뒤 다시 잰 숫자는 '처음 보는 문장' 결과가 아님)

참고: B가 배포 서버에서 새 표현을 써 보며 찾은 문제(검사 이름, 다른 항목이 저장된 상태, 취서 오인식, 할 일 누락 등)는
처음 써 본 시점에 실제로 틀렸던 사례입니다. 지금은 고쳐서 위 86문장에 들어가 있습니다.

## 한계 (질문 대비)
- **테스트 문장은 팀이 직접 만든 86개**입니다. 실제 병원 녹음이 아니며, 오류를 발견할 때마다 문장을 추가했기 때문에
  ③의 규칙은 이 문장들에 맞춰져 있습니다. 처음 보는 표현에서는 정확도가 낮을 수 있습니다 (위 '처음 보는 문장으로 재기').
- 틀린 4문장은 모두 **저장하지 않은 쪽**입니다: "아마 한 달 뒤"·"보건 진료실도 이동하세요"(확인 요청 대신 무시),
  "취서됐습니다"(프론트에서 '취소'로 보정한 뒤 분석, 보정 전 원문은 놓침), "대기 번호를 잘못 안내드렸습니다. 15번입니다."(저장 값은 정답).
- 음성 인식(STT) 오류는 일부 문장(띄어쓰기·문장부호 없음, 한글 숫자, 실제로 들린 오인식 몇 가지)으로만 흉내 냈습니다.
- 실제 AI는 같은 문장에도 답이 조금씩 달라질 수 있습니다. 3회 반복의 최소~최대 차이는 1~2문장이었습니다.
