# 변경 판단 정확도 평가

> 측정일 2026-10-19 · 모델 gpt-4o-mini (temperature 0) · 병원 분야 테스트 문장 70개 × 3회 반복
> 다시 측정: `backend` 폴더에서 `python -m scripts.report --provider openai --repeat 3` (표가 화면에 출력되며, 이 문서의 숫자는 손으로 갱신)

## 한 줄 요약
**같은 AI 답변이라도 규칙 검증을 거치면 틀린 정보 저장이 12건 → 0건으로 줄었습니다.**
반영해야 할 변경을 놓친 경우는 0건 그대로이고, 대신 사용자에게 확인을 묻는 횟수가 2건 → 9건으로 늘었습니다.

## 규칙 검증 효과 (70문장 × 3회, 세 번 모두 같은 결과)

| 판단 방식 | 문장 정답 | 잘못된 저장 | 확인 요청 | 놓친 반영 |
|---|---|---|---|---|
| ① AI 단독 | 55 / 70 (79%) | 12건 | 2건 | 0건 |
| ② 기본 규칙 | 55 / 70 (79%) | 12건 | 3건 | 0건 |
| ③ 안전장치 추가 (현재) | **68 / 70 (97%)** | **0건** | 9건 | 0건 |

- **① AI 단독**: AI가 말한 변경 유형대로 저장 (언급이면 무시, 불확실이면 확인만)
- **② 기본 규칙**: 프로젝트 시작 때의 verifier 8개 규칙 (근거 확인, 신뢰도, 같은 값 등)
- **③ 안전장치 추가**: 실제 AI 오류를 보고 추가한 규칙 (값 정규화, 불확실 표현, 값 형식, 안내 대상, 상태 설명)
- 세 방식에 **같은 AI 답변**을 넣었으므로 차이는 판단 방식에서만 나옵니다.

용어
- **잘못된 저장**: 저장 결과 '현재 정보'가 틀리게 된 문장 수. 같은 값을 다시 저장하거나 '1시'·'오후 1시'처럼 표기만 다른 경우는 세지 않습니다.
- **확인 요청**: 자동 반영하지 않고 사용자에게 물은 횟수. 안전을 위해 치르는 대가입니다.
- **놓친 반영**: 반영해야 하는데 반영하지 않은 항목 수.

## 읽는 법 (발표 포인트)
1. **AI는 대부분 맞히지만, 틀릴 때가 위험합니다.** AI 단독은 79%를 맞히지만 12문장에서 틀린 정보를 저장합니다.
   이 서비스에서는 "모르면 묻기"보다 "틀리게 저장하기"가 훨씬 나쁩니다.
2. **처음 만든 기본 규칙만으로는 효과가 없었습니다 (①과 ②가 같음).** AI는 근거를 지어내거나 신뢰도를 낮게 주는 일이 거의 없었고,
   실제 오류는 "다른 환자를 부르는 안내", "진료실 상태 설명" 같은 **안내 문장 특유의 함정**에서 나왔습니다.
   평가 → 오류 분석 → 규칙 추가를 반복해 ③을 만들었습니다.
3. **대가는 확인 요청 7건 증가입니다.** 70문장 중 9번 사용자에게 묻습니다. 대부분 "내 번호를 등록하면 자동으로 구분해요"처럼
   사용자가 정보를 등록하면 줄어드는 확인입니다.

## 한계 (질문 대비)
- **테스트 문장은 팀이 직접 만든 70개**입니다. 실제 병원 녹음이 아니며, 오류를 발견할 때마다 문장을 추가했기 때문에
  ③의 규칙은 이 문장들에 맞춰져 있습니다. 처음 보는 표현에서는 정확도가 낮을 수 있습니다.
- 정답률 97%에서 틀린 2문장은 **저장하지 않은 쪽의 실수**입니다 ("아마 한 달 뒤" 확인 요청 누락, "보건 진료실도 이동하세요" 확인 요청 누락).
- 음성 인식(STT) 오류는 일부 문장(띄어쓰기·문장부호 없음, 한글 숫자)으로만 흉내 냈습니다.
- 실제 AI는 같은 문장에도 답이 조금씩 달라질 수 있습니다. 이번 측정에서는 3회 모두 같은 결과였습니다.
